逆向面试最毒的20题及答案

1. 什么是OEP？为什么重要？

答案：
OEP（Original Entry Point）是程序的原始入口点，程序执行最开始的指令地址。

  • 加壳程序会修改入口点，防止静态分析。

  • 找到OEP后，可以脱壳、还原程序逻辑。

2. 什么是PE文件结构？主要部分有哪些？

答案：
PE是Windows可执行文件格式，主要部分：

  • DOS头（MZ）

  • PE头（NT Header）

  • 节区（Section Table）：.text、.data、.rdata、.idata等

  • Import Table（导入表）、Export Table（导出表）、资源表等。

3. 静态分析和动态分析的区别？

答案：

  • 静态分析：不运行程序，通过反汇编、反编译分析代码逻辑。

  • 动态分析：运行程序，通过调试、Hook、内存观察分析行为。

4. 什么是控制流混淆？

答案：
控制流混淆通过插入无效跳转、条件分支、循环等改变代码逻辑顺序，使分析难度增加。
处理方法：用静态+动态分析逐步理解逻辑。

5. 什么是Hook？常见类型有哪些？

答案：
Hook是拦截或修改函数调用的技术。
常见类型：

  • IAT Hook（导入表）

  • EAT Hook（导出表）

  • Inline Hook（函数入口插桩）

  • 系统调用 Hook

6. 常见反调试手段有哪些？

答案：

  • 检测调试器存在：IsDebuggerPresent()

  • 异常/SEH检测

  • 检查时间差（Sleep反调试）

  • 调试寄存器检查

  • 反Frida、反x64dbg

7. 你如何绕过反调试？

答案：

  • 修改程序判断值或跳过反调试分支

  • 使用动态调试结合断点

  • 通过内存修改或Hook API绕过检测

8. 常用脱壳方法有哪些？

答案：

  • 找到OEP → 内存Dump → 修复IAT → 生成脱壳文件

  • 工具辅助：OllyDbg + LordPE / IDA + Scylla

9. 什么是栈溢出？如何利用？

答案：

  • 当函数写入数据超过栈分配空间时，会覆盖返回地址或相邻内存。

  • 利用方法：通过溢出控制返回地址，执行shellcode或ROP链。

10. 什么是ROP？

答案：
ROP（Return Oriented Programming）通过已有代码片段（Gadget）组合执行攻击逻辑，用于绕过DEP/NX保护。

11. Windows API Hook原理？

答案：

  • 修改函数入口或导入表地址，让程序调用被Hook后的函数。

  • 用途：监控、拦截、篡改程序行为。

12. 什么是IAT？为什么重要？

答案：
IAT（Import Address Table）保存程序导入函数地址。

  • Hook攻击常修改IAT

  • 静态分析可通过IAT快速定位API调用

13. PE加壳目的？常见壳？

答案：

  • 目的：保护程序逻辑、避免反编译或分析

  • 常见壳：UPX、Themida、VMProtect

14. 如何识别程序加壳？

答案：

  • 用工具：PEiD、Exeinfo、Detect It Easy

  • 特征：节区异常、入口点跳转、虚拟表异常

15. 你分析过加密函数吗？如何识别？

答案：

  • 识别方式：观察可疑循环、查找加密常量、API调用（AES/RC4）

  • 处理方法：静态分析 + 动态调试 + 数据流跟踪

16. 反混淆策略是什么？

答案：

  • 控制流：逐步理解逻辑

  • 字符串加密：跟踪解密函数

  • 虚拟机保护：分析虚拟指令含义，恢复真实逻辑

17. Frida能做什么？

答案：

  • Hook函数调用

  • 修改程序运行行为

  • 动态监控内存和参数

  • 跨平台（Windows、Android、iOS）

18. 你平时逆向工具链是什么？

答案：

  • 静态分析：IDA、Ghidra、Binary Ninja、Radare2

  • 动态调试：x64dbg、OllyDbg、WinDbg、Frida

  • PE分析：LordPE、CFF Explorer、PEiD、Exeinfo

  • 辅助：Python/pwntools、Procmon、Wireshark

19. 常见游戏安全保护措施有哪些？

答案：

  • 防外挂客户端检测

  • Hook / API 监控

  • 内存/数据加密

  • 虚拟机保护 / 控制流混淆

  • 网络通信加密

20. 你做过最复杂的逆向是什么？

答案示例：

我分析过一个强混淆的 Windows 游戏客户端，变量名和函数被彻底混淆，关键验证逻辑加密。
我通过静态分析初步理解控制流程，再用动态调试追踪数据流，最终定位关键函数和加密算法，实现逻辑理解与实验验证。

1 什么是 PE 文件？

标准回答

PE（Portable Executable）是 Windows 可执行文件格式，用于 EXE、DLL、SYS 等程序。
主要结构包括 DOS Header、PE Header、Section Table 以及 Import Table、Export Table 等数据结构。

面试官追问

  • PE加载流程是什么

  • 常见Section有哪些

继续回答

常见Section：

  • .text 代码段

  • .data 数据段

  • .rdata 只读数据

  • .idata 导入表

2 程序加载流程是什么？

回答

Windows加载程序大致流程：

  1. 读取PE头

  2. 分配虚拟内存

  3. 加载各个Section

  4. 处理重定位

  5. 解析Import Table

  6. 跳转到EntryPoint执行

3 什么是 OEP？

回答

OEP（Original Entry Point）是程序原始入口点。
加壳程序会修改入口点，通过壳代码先执行，然后再跳转回OEP。

追问

怎么找到OEP？

回答

常见方法：

  • 动态调试跟踪

一、PE 文件里常见的三种地址

在 PE 文件里常见三种地址概念：

1️⃣ FOA (File Offset Address)
文件中的偏移地址

2️⃣ RVA (Relative Virtual Address)
相对虚拟地址

3️⃣ VA (Virtual Address)
虚拟地址（程序运行时地址）

二、三者关系（核心）

面试最关键的一句话：

VA = ImageBase + RVA

解释：

  • ImageBase：程序加载基址

  • RVA：相对虚拟地址

所以：

虚拟地址 = 程序加载基址 + 相对虚拟地址

这就是计算 VA 的核心。

三、举个简单例子

假设：

ImageBase = 0x400000
RVA = 0x1234

那么：

VA = 0x400000 + 0x1234
= 0x401234

四、RVA 和 FOA 怎么转换

这是面试很可能继续追问的。

转换公式：

FOA = RVA - Section.VirtualAddress + Section.PointerToRawData

解释：

  • VirtualAddress：节区在内存中的起始地址

  • PointerToRawData：节区在文件中的起始偏移

五、举个真实例子

假设：

RVA = 0x1200
Section.VirtualAddress = 0x1000
Section.PointerToRawData = 0x400

计算：

FOA = 0x1200 - 0x1000 + 0x400
= 0x600

六、面试最标准回答（推荐你背）

如果面试官问：

PE 文件虚拟地址怎么计算？

你可以这样回答：

在 PE 文件中虚拟地址 VA 等于 ImageBase 加上 RVA，也就是 VA = ImageBase + RVA。如果需要将 RVA 转换为文件偏移 FOA，需要根据节表计算，通过公式 FOA = RVA - Section.VirtualAddress + Section.PointerToRawData。

这回答 基本满分。
